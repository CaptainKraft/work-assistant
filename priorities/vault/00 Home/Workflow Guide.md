## Core idea

Use Obsidian as the product for now.

- notes are the source of truth
- properties carry structured data
- Bases creates decision views
- briefs communicate decisions to the team

## Suggested workflow

### 1. Capture ideas

- create a note from [[priority]]
- keep it in `status: backlog`
- write the rough problem and maybe a first appetite guess

### 2. Shape promising bets

- fill every fixed heading
- add `strategic_alignment`, `confidence`, and `team_fit`
- add optional RICE, ICE, and delay vs effort inputs if they help
- link likely owners and a cycle when that becomes clear

### 3. Compare candidates

- use the `Compare Candidates` Base from [[Bases Setup]]
- sort by a useful score, then read the note narratives
- keep `Decision Rationale` honest about why one item wins over another

### 4. Select current direction

- move chosen priorities to `todo` or `working`
- assign them to the current cycle
- set `selected: true` if you want a very explicit chosen filter

### 5. Publish a brief

- create or update a note from [[brief]]
- explain what the cycle is focusing on
- explain why these priorities matter now
- explain likely staffing direction and tradeoffs

### 6. Review and close

- move completed items to `done`
- move abandoned items to `cancelled`
- archive old cycle notes and briefs when they are no longer active

## Team fit guidance

Keep this simple and explainable.

- `5` = strong expertise + strong interest + reasonable load
- `4` = strong expertise + acceptable load
- `3` = plausible fit
- `2` = weak fit
- `1` = poor fit

Record the reasoning in `Staffing Notes` instead of trying to fake certainty.
